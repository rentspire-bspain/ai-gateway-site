BoundView docs

Last updated 2026-11-21. Every figure below comes from the repository's QA reports; sources are named next to each number.

What it is

BoundView is a research-and-answer assistant: ask a question and it searches the web and your connected sources, then writes a cited answer. It runs on open-weight models behind a single gateway, and long reports and files open in a side panel next to the conversation. Access is invite-only (see below).

Connected context

Connecting your own accounts turns workspace messages, files, inbox threads, and calendar schedules into cited, searchable context alongside live web search — so one question can cross-reference your documents and conversations with live web sources instead of manual copy-paste:

  • Ask your Slack Live — “What did #ops decide this week on the Q4 rollout, with links to each thread?”
  • Ask your files Live — “Compare the figures in my Dropbox Q3 folder against live market data.”
  • Ask your own inbox Pending registration — “What did my accountant say about the Q3 invoices?”
Privacy contract: Connector credentials and indexed context rows are stored in Supabase as user-owned rows scoped to auth.uid() and enforced at the database layer by Postgres Row-Level Security (RLS) — no other user can read your rows. OAuth authorization codes are exchanged server-side (/api/oauth-callback), so client secrets and refresh tokens never reach browser JavaScript. Only snippets retrieved for your active query are sent to generate the answer; there are no ads, no third-party trackers, and no sale of data. Write actions (sending email or creating calendar events once mail/calendar providers are connected) require clicking an explicit in-chat Approve card. You can disconnect any provider in Settings → Connectors or delete threads and stored files at any time (see Privacy).

The completion program

Progress is tracked against a fixed set of 29 weighted dimensions, scored from live-verified evidence and computed by qa/generate-parity-headline.py from qa/parity-items.json. Nothing is hand-summed. Current headline: 84.4% (10804 / 128 weighted points, version v291b; source: qa-reports/parity-headline-latest.json).

  • Feature parity (17): Features, Computer, API, Troubleshooting, Voice, Account, Models, Connectors, Privacy, Comet, Premium, Enterprise, Getting Started, Desktop, Billing, Mobile, Teammates.
  • Product surfaces (12): UX, SEO, Marketing, Security, Accessibility, Legal/Compliance, Docs/Support, Observability, Fleet, Email/Notifications, i18n, Native Mobile.

Several dimensions score well below 100 (for example Mobile 60, Accessibility 55, Legal/Compliance 45, i18n 10). Partial credit counts as half.

Standing post-deploy checks

No deploy counts as done until these three suites pass against the live site:

  • qa/e2e-real-flows.py: 9 shell flows (app loads, no CSP violations, no runtime errors, real auth errors shown, no brand leaks).
  • qa/e2e-ux-flows.py: 9 UX flows.
  • qa/e2e-ux-master.py: 46 weighted checks, passing at 90 or above.

Access

BoundView is invite-only. There is no open signup; sign-in with an uninvited email shows an invite-only message. To request access, contact the owner of the deployment you were pointed to.
